# iOS 26 本机字幕：语言选择与产品实验

本文记录 Turbo IO iOS V1 中 Apple 本机识别、本机翻译和字幕显示的实际行为。设置入口为「字幕 → 字幕设置」。这里的“检测”分为模型支持检查与文字语言识别；它们都不是对尚未采集的声音做语言识别。

## 语言与模型准备

- 首次建立字幕设置时，App 将识别语言设为中文（`zh-CN`）。底层通用 `CaptionOptions` 的初始值是 `en-GB`，但字幕设置会覆盖它；升级用户可能继承已保存的语言，因此以设置页显示值为准。
- Apple `SpeechTranscriber` 每次会话使用一个指定的语言。准备本机识别模型时，App 检查该语言是否受支持、系统实际匹配的 locale 和资源是否已安装；需要时请求下载。准备动作本身没有音频输入，因此不能判断说话人讲什么语言。
- 准备本机翻译模型时，App 根据所选识别语言确定语言对：中文识别翻成英语，英语识别翻成中文。翻译只处理一句话结束后的文字；资源准备也不会从麦克风自动判断语言。
- 设置中的样本文字检测使用设备上的文字语言识别，只接受足够长且结果明确的中文或英语样本。检测结果可以供用户选择识别语言，随后仍需按所选语言准备识别模型与翻译模型。运行中对最终识别文字的语言不匹配检查仅产生诊断，不会在同一次会话中无提示地切换识别模型。
- 因为英语英国与英语美国的文字通常无法可靠区分，样本文字检测只判断“英语”，具体使用 `en-GB` 或 `en-US` 仍由用户选择。
- 繁体中文的文字检测结果不会直接改成 `zh-CN`：字形无法证明说话人的语音模型应使用哪个地区语言。

## 实时显示规则

Apple 本机识别返回的临时结果用于流式原文；最终结果进入历史记录，并在开启本地翻译时排队翻译。默认的连续对话显示顺序是：

1. 第一句的最终原文先显示，翻译完成后按语言模式显示译文或中英双语。
2. 第二句一开始产生临时识别结果，就用第二句正在识别的原文覆盖上一句的显示，并持续刷新。即使选的是只看译文模式，默认仍暂时显示第二句原文，避免用户在译文生成前看不到新说话内容。
3. 第二句最终原文继续显示到译文就绪；译文就绪后按当前语言模式替换。若上一句译文来得太晚，它仍可保存到历史记录，但不会覆盖正在显示的较新句子。
4. “最终字幕停留”从最终字幕成功显示时开始计算；下一句临时原文会优先占据显示区。停留到期后清空当前字幕。

产品实验区提供“新句流式原文优先”开关，用于比较上述默认行为与保留上一句译文的行为。最终字幕可选择直到下一句，或自定义 0–30000 毫秒；0 表示尽快清空。低延迟与高保真翻译策略也供产品比较：高保真在设备支持且启用 Apple Intelligence 时可能更流畅但更慢，系统条件不满足时会回退。

### 显示时序实验参数（build 21）

所有时间输入都以**整数毫秒**显示和编辑，滑杆连续拖动，没有固定的 3/5/10 秒步长。参数作用在显示状态，不延迟音频采集、识别或保存：

| 参数 | 范围 | 默认 | 生效点 |
| --- | ---: | ---: | --- |
| 临时原文更新间隔 | 0–1000 ms | 0 ms | 合并同一句的快速临时识别更新；0 表示不额外合并。 |
| 新一句接管延迟 | 0–1000 ms | 0 ms | 从新句第一次临时识别结果算起；到时显示最新临时原文。0 表示立即接管。 |
| 定稿原文最短可见时间 | 0–3000 ms | 0 ms | 本句原文定稿后，译文不能早于这个时刻替换它。 |
| 译文就绪后额外等待 | 0–3000 ms | 0 ms | 译文实际返回之后再等多久显示。最终接入时刻取它与上一项期限中较晚的一个。 |
| 最终字幕停留 | 0–30000 ms，或直到下一句 | 直到下一句 | 从本句最终显示或成功发送给眼镜的时刻算起；新句接管仍可提前覆盖。 |
| 眼镜文字发送间隔 | 500–2000 ms | 500 ms | type-5 字幕指令的最短发送间隔；保留 500 ms 下限，不允许无限速发送。 |

这些时间是 App 的调度目标。手机 UI、系统调度、识别结果到达时刻和眼镜链路都可能带来误差；**毫秒输入不等于 1 ms 的屏幕刷新保证**。眼镜尤其受文字发送间隔限制：很短的字幕可能还未轮到发送就被下一句取代。预览以毫秒时间轴演示连续对话、快速插话、极短应答和翻译失败，实际眼镜表现仍以真机为准。

## 真机检查建议

1. 在 iOS 26 设备上先选中文，确认“准备本机识别模型”显示所选语言和系统匹配语言；再准备中→英翻译语言包。改为英语后重复，确认语言对变为英→中。模型下载需要网络；字幕运行时不上传 Apple 本机识别音频。
2. 用长度足够的中文、英文样本分别检测文字语言，确认检测只给出中/英建议，且不会在活动会话中修改识别语言。短句或混合语言样本应提示结果不确定。
3. 开启本地翻译，分别选只看中文、只看英文和中英混合；连续说两句，中间不要长时间停顿。确认第二句仍逐步显示原文，第一句迟到的译文不会盖回第二句。
4. 分别输入 0、100、750、1000、5000 ms 停留，以及“直到下一句”，观察手机与眼镜字幕。对 0–1000 ms 的实验应记录实际出现和消失时刻，不应把设置值当作精确实测延迟。检查在翻译失败或语言包缺失时，历史中只保存真实原文，显示区出现明确的回退状态。
5. 调高新句接管、定稿原文最短可见和译文就绪后等待，确认每个参数只影响对应阶段。快速插话时，旧句译文即使晚到也不能覆盖已识别的新句；在眼镜上比较 500 ms 与更长发送间隔。
6. 在产品实验区比较低延迟与高保真策略，记录每句最终识别、翻译完成及显示的延迟；高保真是否真的使用 Apple Intelligence 取决于设备与系统设置。
7. 在语音尚未定稿时停止会话，核对最后一段临时文字是否按 `unfinished` 保存。当前停止流程不会等待 Apple 识别器处理完全部缓冲音频，因此不能把这段内容称为最终识别或保证它有译文。

这些是验收步骤，不代表已经完成真机验证。GitHub Actions 的 iPhoneOS 编译只能验证构建，不能替代连续对话、语言包下载和眼镜显示的真机检查。

## Apple 接口依据

- [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber)：转写器以 locale 创建，并可查询支持与已安装的 locale。
- [NLLanguageRecognizer](https://developer.apple.com/documentation/naturallanguage/nllanguagerecognizer)：识别已有文字的语言；不是音频语言识别器。
- [prepareTranslation()](https://developer.apple.com/documentation/translation/translationsession/preparetranslation%28%29)：没有源语言且没有样本文字时，无法通过准备动作识别源语言。
- [TranslationSession.Strategy](https://developer.apple.com/documentation/translation/translationsession/strategy)：低延迟与高保真策略的定义及回退行为。
