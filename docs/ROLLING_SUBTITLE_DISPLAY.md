# 分区滚动字幕 · 0.4.0 (22)

实时字幕默认使用连续滚动窗口。识别服务返回 final 只确认文字，不清屏；原文和译文分别维护历史与未确认尾部。新原文不会取消旧段译文的显示机会。

## 推荐配置与产品工作台

入口：字幕 → 设置 → 字幕产品工作台。参数会保存在本机，重启后恢复；保存和恢复推荐配置不会开启收音或自动打开翻译。

| 参数 | 默认 | 可调范围 |
| --- | --- | --- |
| 显示方式 | 滚动分区 | 滚动分区、按段替换 |
| 原文 / 译文行数 | 3 / 2 | 原文 1–4，译文为剩余行，共 5 行 |
| 滚动单位 | 行 | 行、词；中文词模式按字符推进 |
| 换行宽度 | 28 | 16–40 个宽度单位；汉字通常占 2，拉丁字符通常占 1 |
| 流式原文更新间隔 | 0 ms | 0–1000 ms，眼镜仍受发送间隔限制 |
| 译文最短停留 | 1500 ms | 0–5000 ms |
| 译文就绪后延迟 | 0 ms | 0–3000 ms |
| 眼镜最短发送间隔 | 500 ms | 500–2000 ms |
| 保留方式 | 持续保留 | 可选在识别、翻译与显示队列处理完成并静默后清空 |

双语时原文固定在上、译文固定在下。单语模式使用全部五行。原文和译文可以属于前后不同段，译文允许落后于正在说的话。长译文按行或词逐步进入下区，避免一次性只保留最后两行。眼镜输出连接正常时，译文阅读停留从包含该译文的文字包成功提交后开始；这仍不是镜片实际呈现的 ACK。

旧安装缺少新布局字段时采用推荐滚动布局，保留已保存的语言、翻译开关与其他时序选择。工作台保留按段替换用于对照；新句接管、原文最短可见与上下顺序只用于该模式。连续对话预览使用同一个滚动布局引擎，模拟原文先推进、上一段译文稍后返回。

## 显示边界

当前协议仍发送一个 `source_transcript` 文本字段。App 先按宽度估算换行，再补足五个逻辑行；每行最多 76 个 UTF-8 字节，加上换行后整个包不超过 384 字节。字素不会被拆开。空行用空格占位。

固件是否保留空行、实际字体宽度及五行的位置，需要眼镜验收。宽度 28 是保守的起始配置，可在工作台校准。词模式是文字窗口推进方式；当前不承诺镜片原生滑动动画。翻译任务及待显示队列总量设有上限，超出时提示积压并保留原文；有限的两行无法保证任何语速下都能完整阅读。

## GitHub Actions 编译

沿用 `.github/workflows/ios-rollback-build.yml`：推送到功能分支后对该分支运行 `workflow_dispatch`，或由匹配源码路径的 PR 触发。使用已验证的 macOS 26 / Xcode 26.6 配置。

新增编译前检查：

1. `swift test --package-path rayneo-captions`：布局、修订、独立翻译序号、Unicode 与包大小。
2. `node scripts/test-subtitle-rolling.mjs`：iOS 26 模拟器上的实时字幕回归与设置保存、迁移测试。
3. 生成设备工程并编译未签名 iPhoneOS App。
4. 打包 `TurboIO-iOS26-v0.4.0-build22-unsigned.ipa` 与 `SHA256SUMS.txt`，上传 Actions artifact。

IPA 需沿用已有个人签名流程安装。通过编译与模拟器测试后，仍需真机确认分区换行、连续讲话期间的译文、长译文逐行显示以及停止和重连后的清理。
