# 演讲提词器 · 0.4.0 (27)

主导航的“提词”入口管理多篇稿件与演讲。语音跟随适用于以稿为主、少量临场发挥的演讲。识别结果只用于定位原稿，不替换稿件或生成回答。

## 稿件与演讲

- 新建、编辑、重命名、复制、搜索、选择、分享、TXT/MD 导入和确认删除。
- 单篇最多 12,000 字、48,000 UTF-8 字节，最多 100 篇；本机原子保存，排除 iCloud 备份。
- 记住选中稿件和每篇阅读位置。旧单篇草稿迁移一次；原稿不会静默截断。
- 演讲使用不可变稿件快照，结束后再切换、编辑或删除。
- 手机语音跟随、眼镜语音跟随、手机匀速滚动与原有眼镜匀速提词均可进入。匀速模式不启动识别。
- 稿件卡片提供独立的“打开匀速提词”入口。演讲页两种模式均有固定在底部的启动按钮；打开已存在的眼镜匀速会话时恢复匀速模式。
- 眼镜匀速的开始意图由会话控制器持有，只有文件发送成功和眼镜完整收稿同时确认后启动。关闭或重建界面不会丢失这一步，取消、失败和断连会清除意图。
- 手机匀速等待真实文字排版后再判断结尾，短稿也保留尾部滚动空间，改变字号保留当前进度。

## 跟随逻辑

1. 在当前位置附近匹配连续识别内容。忽略大小写、标点和可归一化的字符差异，容忍有限的错字、漏字和口头语。
2. 候选位置与确认位置分开。相同临时结果重复回调不增加证据，较短的定稿片段累积成连续证据。
3. 匹配只提供滚动目标。显示位置与识别位置分开，按原文完整字素限速前进；一句较长的定稿不会直接跳页。
4. 默认只局部向前推进，不自动倒退或全文跳转。重复句存在多个解释时保持位置。
5. 停顿、插话、临场回答或匹配不确定时保持原位，继续收音；附近稿件重新匹配后自动恢复。
6. 手机拖动、点选、方向键和眼镜滑动都是辅助定位：重新建立起点、清理旧候选证据，保持识别会话。
7. “暂停跟随”与“结束演讲”分开：暂停锁住自动推进并继续识别，辅助定位仍可用；结束才停止收音。
8. 识别网络短暂断开时保留位置，按 1、2、4 秒尝试恢复，仅保留有界 PCM 缓冲。配置、认证或耗尽重试时停止并保留稿件位置。

长时间没有音频帧时，保持位置并提示检查输入，仍保留监听；音频重新到来后用新证据定位。明确的麦克风故障或眼镜断连才结束当前收音，避免把停顿、静音门限和包缺失混为正常阅读进度。

匹配单位为归一化字符，原稿位置始终使用原文 UTF-8 字素边界。产品默认相似度 0.60、最少 4 单位、确认 1 次、局部前进范围 96、回看 24、前看 240。重复句仍需位置唯一；识别到远处也只能限速滚动，不能直接跳段。底层匹配库继续保留较谨慎的独立默认值。

## 提词设置与高级设置

稿件库和演讲页的齿轮均进入“提词设置”。首页提供默认提词方式、常用速度、旋钮幅度和调试开关；“高级设置”收纳匹配阈值、确认次数、查找范围、各类等待时间、输入音量阈值、眼镜排版及诊断。参数自动保存在本机，可恢复推荐值。眼镜排版和开场倒数用于下一次传稿启动。

切换调试开关、旋钮倍率、眼镜排版和匀速参数，不清除语音识别证据，不重启麦克风或 ASR。修改匹配及跟随运动参数才重新对齐显示位置，保留暂停或手动辅助之后的旧回调屏障。

| 参数 | 推荐值 | 作用 |
| --- | --- | --- |
| 跟随最高速度 | 12 字素/秒 | 限制连续推进速度 |
| 滚动更新间隔 | 0.15 秒 | 手机光标和眼镜位置指令频率 |
| 手动辅助等待 | 1 秒 | 旋钮或滑动后给主讲人重新对齐的时间 |
| 静音等待 | 2 秒 | 无讲话活动时停止自动滚动，识别继续 |
| 匹配有效期 | 3 秒 | 旧结果不能无限延长滚动 |
| 声音活动阈值 | 0.025 RMS | 区分讲话活动和静音；可按输入音量校准 |
| 匀速模式 | 眼镜 120、手机 24 点/秒 | 独立调速，不启动语音识别 |
| 匀速旋钮辅助 | 自动继续开启、停留 1.2 秒 | 回滚后从新位置按原速度向前；连续回滚延长停留，明确暂停保持停止 |
| 旋钮滑动倍率 | 3 倍，范围 1～8 倍 | 放大眼镜实际回报的原文移动量，保持完整字素边界 |
| 手机滚动回报过滤 | 0.3 秒，范围 0～2 秒 | 过滤程序滚动产生的近期回报，避免旋钮放大循环 |
| 眼镜排版 | 字号 18、宽 492、行距 4、倒数 3 秒、高度档 3、距离档 1 | 准备、开始、调速均保持完整原生显示参数 |

工作台显示识别文字、已匹配位置、实际显示位置、输入音量及眼镜最近控制类型，便于核对旋钮触发的是滚动、设置还是文稿列表。手机按 TextKit 的真实换行位置平滑滚动，不再按大段文字块跳转。

### 手机语音跟随调试模式

可在演讲页直接点击“调试”，或在设置开启“显示跟随调试信息”。手机演讲页显示 ASR 原文、临时或最终结果、匹配相似度、最近匹配字或英文单词、待确认位置、显示位置和输入音量。即使稿件显示在眼镜上，这些信息仍在手机可见。识别预览保留最新尾部内容，展开后显示更长片段。稿件以不同颜色标出最近匹配位置和显示光标；中文、英文、组合字符和 emoji 均按原文完整字素映射。

“最近匹配字”是文字对齐得到的近似端点，不表示 ASR 能判断正在发音的精确字母。暂停时识别文字继续更新；匹配不确定时显示等待确认，人工滑动不伪装成语音识别结果。调试信息只在内存显示，不自动保存识别日志。

### 旋钮幅度

倍率放大真实眼镜位置回报的移动量，不假设镜片每行固定字数，也不改写用于显示高度的原生 `gear`。1 倍保持原来的移动量。语音提词会对有效辅助回报应用倍率；匀速模式对回滚或暂停期间的辅助应用倍率，正常向前播放进度不放大。修正位置在眼镜回应后才作为新的辅助锚点，旧自动回报不覆盖旋钮位置，识别保持运行。

眼镜匀速模式把已开始会话中的向后位置回报作为回看辅助，暂时暂停并在最后一次回滚后继续，不换稿、不重新传输、不恢复到回滚前的位置。普通向前进度不延长辅助等待。手机“暂停”、单独的眼镜暂停请求、进入列表、退出或断连都会取消自动继续；辅助期间可选择“保持暂停”。部分固件可能先报暂停再报回滚：仅在可调的关联窗口（默认 0.6 秒）内出现有效回滚时，将两条消息推断为一次旋钮辅助。单独暂停不设恢复定时器，超出窗口后回滚也不恢复。该判断属于应用层事件关联，可将窗口设为 0 关闭，实际固件事件顺序需真机核对。

文字匹配不能独立证明说话人身份：如果别人恰好念出稿件下一句话，仍可能匹配。演讲时优先使用靠近主讲人的收音；发生误跟随时可滑动辅助或明确暂停。

## 收音与眼镜控制

- 复用字幕设置中的识别服务、语言和密钥，不使用翻译或 AI 对话模型。
- 眼镜麦克风使用同一原生提词会话（business 20），`scroll=1`；iPhone/系统麦克风使用手动提词显示 `scroll=3`，无需另起实时字幕会话。
- 系统输入由 iOS 路由选择，可使用系统提供的领夹麦克风/耳机输入。界面显示实际输入，失败不会静默改用其他来源。
- 临时传稿文件名必须严格等于稿件 DID，没有 `.txt` 扩展名；传给 SDK 的 `extra` 仍为同一 DID，SDK 返回的任务 ID 单独保存。
- 收到准备 `code=1` 后只提交一次文件。重复 `code=1` 不表示收稿完成；必须同时收到原生文件发送成功和 `type=2/action=2/code=7`，才允许开始提词。
- 原生准备、完整收稿、开始回应后才推进；位置通过 type 8 的 `pageOffset/highLightOffset/autoSync=false` 提交，两种偏移使用同一个完整原文边界，不把手机估算行首发给眼镜。发送间隔可调，原生请求按回应串行并合并最新待发位置。
- 手机显示传输阶段、SDK 进度和固定失败类别。本地网络权限、BLE 不可用及 AP 不可用分别提示；失败信息在退出后保留到下一次准备，避免眼镜报错但手机无提示。
- 同设备、活动自有会话内的眼镜进度回传辅助定位。最近程序定位的匹配回报不会重置语音证据。
- 收音和稿件显示由 App 管理，与字幕、智记、录音和 AI 会话互斥。保存设置不启动收音。
- 音频仅在内存中送入所选 ASR，不生成音频文件。阅读位置最多每 2 秒保存，辅助和结束强制保存。

### 原生音频静态依据

本机官方 Android 包的常量表给出 `followSpeak=1`、`linearScroll=2`、`manual=3`，提词器 `audioData=9`。插件接收路径 `LE3/V.i` 对提词业务解析 `TransportMessage.AssistantMsg`，type 9 分支读取 protobuf field 4 的 `data`；随后 `LD7/n.j` 把原始 Opus 交给 `AudioRecorderAdapter.notifyRecordData`，不读取 JSON、DID 或序号。

App 因此先按同一连接及已开始的自有提词会话隔离 type 9，再提取有界二进制并严格解码，不把音频当 JSON，也不猜造序号。官方代码和包只用于本机协议核对，不作为源码提交。

静态依据和模拟测试不能替代真机：眼镜提词收音、Opus 格式、旋钮实际触发类型、固件滚动动画、手动位置映射、锁屏和长时间演讲仍需实测。手机排版不等于镜片像素布局。
