# iOS 26 本机实时字幕接入说明

适用构建：Turbo IO iOS V1 `0.4.0 (14)`，最低系统版本 iOS 26。本文记录实现边界、真机检查步骤和脱敏诊断字段。代码编译及真机表现以对应 GitHub Actions 产物和实际安装结果为准。

## 处理链路

字幕设置提供三种互斥的音频来源：

| 来源 | 采集与处理 | 眼镜条件 |
| --- | --- | --- |
| 眼镜音频流 | 业务 19 音频包 → Opus 解码 → 16 kHz 单声道 PCM → 所选识别引擎 | 必须连接；可切换“前方 / 四周” |
| iPhone 内置麦克风 | 指定内置输入端口 → AVAudioEngine → 16 kHz 单声道 PCM → 所选识别引擎 | 不需要眼镜 |
| 系统麦克风 | 跟随系统录音输入或指定系统可见端口 → AVAudioEngine → 同上 | 不需要眼镜 |

手机麦克风使用前请求系统录音权限，并在启动后核对实际输入端口。指定端口不可用或系统未切到该端口时直接报错；录音中路由变化、中断或队列积压会停止会话并保存已收到的内容。“系统麦克风”指系统提供给本 App 的录音输入，不包括其他 App 的播放音频。

眼镜作为音源时，沿用实时字幕业务 19 的收音启动、Opus 音频、文字显示、停止及 `direction` 设置。用户已在 build 13 真机验证“前方”模式抑制两侧声源，“四周”可收到侧方声源。手机麦克风作为音源时，若用户开启“同时显示在眼镜”且眼镜已连接并空闲，只走已验证的显示协议 `type 7 → type 8 → type 5 → type 3`；不会发送眼镜收音启动命令。眼镜显示失败或断连时，手机收音和手机字幕继续。

## 本机识别与翻译

选择“Apple 本机识别”后，`SpeechTranscriber` 与 `SpeechAnalyzer` 接收上述 PCM。首次使用需准备所选语言的模型；启动前再次检查设备、语言和模型状态。当前字幕设置使用明确的中文或英文语言，Apple 本机识别不使用自动语言检测，也不需要 API Key。模型由 iOS 管理，其支持情况以真机查询结果为准。

“本地翻译”独立于识别服务，可与本机或云端识别组合。固定中文识别语言的目标为英文；固定英文识别语言的目标为中文。设置页通过系统 `translationTask` 请求下载语言包；运行时只使用已安装语言包，对**最终字幕**逐句翻译。原文先显示并归档，译文随后显示并以独立 `translation` 记录归档。暂定识别结果不触发翻译。

## 设置与诊断

字幕设置保存音源、指定系统端口 UID、翻译开关、眼镜显示开关、服务、语言及收音方向。端口 UID 只留在本机设置中；“分享脱敏诊断”只输出音源类别、实际端口**类型**、模型与语言包状态码、包数、PCM 字节数、缺口数、有限的控制协议事件和延迟计数。不得把设备名、端口 UID、音频、字幕正文、密钥或原始序号放进脱敏诊断。

排障时先看实时页的“实际输入”名称是否符合预期，再分享脱敏诊断。若识别没有开始，依次检查录音权限／输入路由、识别模型或云服务连接、本地翻译语言包状态。眼镜音源还需核对业务 19 启动回执、方向指令和音频包增长。

## Actions 构建与真机检查

`.github/workflows/ios-rollback-build.yml` 使用 macOS 26、Xcode 26.6 和 iOS 26 SDK 构建设备目标，关闭代码签名，上传 `TurboIO-iOS26-v0.4.0-build14-unsigned-ipa` 与 `SHA256SUMS.txt`。IPA 需要用户自行签名后安装；Actions 编译通过不等于真机功能验收。

建议在已签名安装后逐项检查：

1. Apple 本机识别分别准备中文、英文模型；确认无 Key 也能开始，并观察暂定与最终字幕。
2. 准备中文→英文和英文→中文翻译语言包；确认原文先显示、译文随后出现，历史导出同时含原文与译文。
3. 在无眼镜时分别用 iPhone 内置麦克风、系统当前麦克风开始，核对实际输入路由及音频包数增长。
4. 连接眼镜并启用“同时显示在眼镜”；确认眼镜只显示手机麦克风的字幕，眼镜断连时手机字幕继续。
5. 切到眼镜音频流，用侧方声源对比“前方 / 四周”，检查切换指令后音频包数继续增长。
6. 测试录音权限拒绝、指定端口拔出、来电中断、模型或语言包尚未下载时的提示与保存行为；分享脱敏诊断检查无正文和设备名。
